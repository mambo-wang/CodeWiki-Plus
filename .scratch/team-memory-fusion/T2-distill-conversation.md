  ## Agent Brief

  **Category:** enhancement
  **Summary:** 新增 MCP 工具 `distill_conversation`，用 LLM 把原始对话蒸馏为语义原子草稿 note，经现有确认门入知识库。

  **Current behavior:**
  现有 `ingest_note` 能把人工/agent 整理的笔记写入 `repowiki/notes/` 并经 `confirm_note`/`reject_note` 确认。但没有任何能力从原始对话自动产生这些草稿——提醒者需手动整理。

  **Desired behavior:**
  新增 `distill_conversation`，作为**无状态 MCP 工具**：读取 `repowiki/raw/<session>.md`，返回蒸馏出的 L1 语义原子草稿（含 note_type、source 引用），**自身不持有/不配置 LLM**。LLM 能力由**调用方注入**——推荐由 IDE subagent 子代理调用（天然使用 CodeBuddy 自带模型，免配 LLM、上下文隔离、异步不阻塞主线程）；也可由 `BackgroundWorker` 调用（此时需 `MAIN_MODEL`/`LLM_BASE_URL` 已配置）。蒸馏出的草稿通过现有 `ingest_note` 以 `status='draft'`（未确认）写入，必须经由 `confirm_note` 才进入正式 `notes/`；`reject_note` 直接丢弃。每条草稿 frontmatter 含 `origin: conversation` 与 `source_conversation`（指向 raw 文件的 turn 区间）以满足可追溯。蒸馏应跳过无意义闲聊，只产出决策级内容，并产出去重后的草稿（见 T3）。**关键约束**：蒸馏是 LLM 重活，必须在后台（subagent 或 worker）异步执行，主线程不等待其完成。

  **Key interfaces:**
  - 新 MCP 工具 `distill_conversation`，入参为 `raw_path`（或 session id），出参为生成的草稿 note 列表（含 note_type、source 引用）。
  - 工具**无状态**：不内部 new LLM client；所需 LLM 由调用方（subagent/worker）在调用前准备完毕，工具只负责编排"读 raw → 调 LLM（由调用方提供）→ 落 draft"。
  - 复用现有 `ingest_note` handler 路径创建 draft（`status='draft'`），**不**新建确认门。
  - 草稿 frontmatter 扩展字段：`origin`、`source_conversation`。
  - **Raw 清理职责**：当 `capture_conversation` 未设 `keep_raw` 时，在对应 raw 的草稿全部经 `confirm_note`/`reject_note` 处理后，best-effort 删除 `repowiki/raw/<session>.md`，避免暂存区无限膨胀。

  **LLM 路径（执行方选择其一）：**
  - 路径 A（推荐）：IDE subagent 调用 → 使用 CodeBuddy 自带模型，免配 LLM、隔离上下文、异步不阻塞。
  - 路径 B：`BackgroundWorker` 线程调用 → 需 `MAIN_MODEL`/`LLM_BASE_URL` 已配置（参考 `codewiki/src/fe/background_worker.py` 的 LLM 接线）。

  **Acceptance criteria:**
  - [ ] 给定一段含明确决策/教训的 raw 对话，产出对应 `note_type` 的草稿 note。
  - [ ] 草稿以 `status='draft'` 写入，未经 `confirm_note` 前不可被 `query_wiki` 作为正式笔记检索到。
  - [ ] 每条草稿含 `origin: conversation` 与 `source_conversation` 引用。
  - [ ] 闲聊/无意义内容不产生草稿（signal-dense）。
  - [ ] 复用既有 `ingest_note` 持久化/索引路径，无第二套写入逻辑。
  - [ ] 工具本身不持有 LLM 接线；LLM 由调用方注入（可在测试中显式传入 stub/mock LLM 验证）。
  - [ ] 有 LLM 提取的 golden-set 测试（防幻觉回归）与一条 handler 层测试。

  **Out of scope:**
  - L2 场景聚类 / L3 画像（spec 已排除）。
  - 透明代理注入（MemoryProxy 式）。
  - TAM 代码依赖。
