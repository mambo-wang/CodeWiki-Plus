  > *This was generated by AI during triage.*

  ## Agent Brief

  **Category:** enhancement
  **Summary:** 监听 IDE 对话事件，自动调用 `capture_conversation`，实现对话经验无感采集（手动触发之外的可选路径）。

  **Current behavior:**
  `capture_conversation`（T1）已实现为 MCP 工具，但目前只能由用户/Session 结束时手动调用。CodeWiki-CN 没有在对话发生时自动采集的机制。

  **Desired behavior:**
  新增可选的 IDE 自动采集层：在本仓库的 agent 运行环境中监听对话事件（如用户消息提交、assistant 回复落库、会话结束），将 turns 自动送给 `capture_conversation`。应满足：
  - 不阻塞正常对话流（异步/非阻塞写入）。
  - 可开关（默认关或由配置项控制），避免无感写入打扰用户。
  - 与 T1 工具共用同一落盘路径 `repowiki/raw/<session>.md`，幂等覆盖。
  - 不引入 TAM 代码或额外服务；尽量复用本仓库已有的 agent 钩子/事件机制（参考 `.codebuddy/` 技能钩子约定或现有 hook 接入点）。
  - **边界明确**：自动采集层**只负责落 raw**（调用 `capture_conversation`），**不触发蒸馏**。蒸馏（LLM 重活）由 `distill_conversation` 经 subagent/BackgroundWorker 另行走后台执行，不在此层内，避免自动采集路径意外引入 LLM 接线与阻塞。
  - **生命周期一致**：自动采集落下的 raw 与手动 `capture_conversation` 同属暂存区，遵循同一套清理策略（蒸馏完成后由 T2 删除；默认 7 天保留上限自动清理）。自动采集**不**额外持有或缓存对话副本，避免重复膨胀。

  **Key interfaces:**
  - 复用 T1 的 `capture_conversation` handler（不重写采集逻辑）。
  - 接入点：本仓库 agent 事件/hook 机制；若无现成接入点，新增一个最小监听器，调用 `capture_conversation`。
  - 配置项：启用开关（如 env 或配置段），默认关闭。

  **Acceptance criteria:**
  - [ ] 开启自动采集后，一次对话结束能在 `repowiki/raw/` 生成对应 session 的 turns 文件。
  - [ ] 关闭开关后，不发生任何自动写入。
  - [ ] 自动写入为异步/非阻塞，不拖慢对话响应。
  - [ ] 与手动调用 T1 写入同一路径且幂等，不冲突。
  - [ ] 有测试或冒烟验证覆盖"事件触发 → capture_conversation 被调用"。

  **Out of scope:**
  - 自动蒸馏（蒸馏仍由 `distill_conversation` 手动或另行触发）。
  - MemoryProxy 式实时注入。
  - TAM 代码/Node 依赖。

  **Depends on:** T1（capture_conversation 工具必须先就绪）。
