## Background

为公众号文章（`articles/2026-10-13-better-harness-作用原理与使用全解.md`）补四张流程图时，用户提出硬约束：「生成的图片一定要考虑手机上阅读是否能看清楚，我是要用来发公众号的」。首版按桌面习惯设计 1180px 宽、11.5–13px 字号，在手机上完全不可读，返工重做。

## Procedure（验证过的手机可读信息图管线）

1. **按显示宽度反推设计参数**：公众号正文栏宽约 351 CSS px。设计画布取 640 单位，字号正文 22–24、标题 32–34、下限 21——渲染后正文约 12–13 CSS px（公众号正文 15–17px 的 71–85%），标题超过正文。字号预算定了，每行字数就定了（640 宽减边距约 23 个汉字/行），内容密度必须跟着砍，细节留在正文文字里。
2. **竖排优于横排**：手机可滚动，高图（如 640×956）没问题；横向并排卡片会挤成窄条。
3. **SVG→PNG 必须转**：公众号编辑器不接受 SVG。用 Playwright `chromium.launch({channel:'msedge'})`（免下载 chromium），`deviceScaleFactor: 3` 截图导出 PNG。
4. **验证闭环不能省**：写一个 351px 栏宽的 HTML 预览页，`page.goto('file:///...')` 打开后对每张图做元素级截图，用视觉检查确认可读。注意 `page.setContent()` 内嵌 `file:///` 图片 src 会得到 `naturalWidth===0` 的坏图，必须落盘真实 HTML 再 goto。
5. **常见渲染缺陷**：卡片内末行文字基线越过卡片底边（裁切）——合并成单行或加高卡片并重排下游所有 y 坐标；语义截断（「后续可比」应为「结果支持」）。

## Rationale

值得持久化：下次给公众号/移动端做配图可直接走这条管线，避免一次完整返工；「按目标显示宽度反推字号」是通用方法论，不限于公众号。
