**场景**：增量分析要回答哪些 Markdown 页面引用了被删除或改名的组件，而反向索引本身又是可删除、可重建的派生元数据。

**做法**：以 Markdown 为唯一内容真源，从链接、wikilink、component ID，以及 fenced/inline code 中的唯一符号建立双向引用。改名只认同一 relative_path/start_line/end_line/component_type 且一对一的新旧组件；普通散文同名单词不算符号引用，同名胜者不建立映射。历史唯一符号映射持久化到 SQLite repo_meta.reference_symbols，不能只留在待删除的 reference_index.json 中。索引不写时间戳，key 与清单排序，原子写入且 stage=False，并注册为 rebuildable。

**边界**：analyze_repo 只返回 component_changes 与 referencing_pages，正文改写由宿主 Agent 决定；不新增 MCP 工具，不改变 confirm/lint 闸门。

**验收**：索引删除或损坏后可重建；旧符号仍能定位引用页；工具不改文档正文；全量回归 1434 passed/2 skipped。
