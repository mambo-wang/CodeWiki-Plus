## 结论

借鉴上游时不能把提交数量或 patch-id 当成本地缺口；本地是 squash 加手工改写历史，最终必须以当前源码核对功能是否已存在。CodeWiki 上游 050dd26..f07bb46 的真增量主要是 legacy CLI/内置 backend/组件级 updater，与 CodeWiki-Plus 的 MCP 工具 + 宿主 Agent + job/change_plan 主线分叉，因此不整仓 merge。

## 可复用处置

1. correctness/stability 小修优先：解析超时异常不应被分析器内部 except Exception 吞掉；JS/TS 构造器需进入组件图；C/C++ 要沿 declarator 包装层识别真实函数名；Git 子进程用 DEVNULL 脱离 MCP stdio；Mermaid 远程校验用 daemon thread，避免超时后阻塞解释器退出。
2. 上游 updater 只抽确定性机制：反向引用索引回答哪些页面引用被删除/改名组件；ownership closure 为无 owner 变更产出候选；tree repair 在工具层做重命名/删除/同目录归位；write guard 默认 observe，再升级 enforce。
3. 聚类改进落成 validator：完整文件 token、同文件不可拆模块、微页/漏文件诊断，默认观察不自动重排。
4. 新语言、UsageLedger、artifact 与 standalone provider/交付能力按真实仓库需求引入，不一次搬全套。
