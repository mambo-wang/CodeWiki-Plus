## 背景

宿主 Agent 可直接调用 write_doc_file/edit_doc_file，旧逻辑只防目录逃逸，无法判断页面是否属于本轮 change_plan；仅按 stem 匹配还会让 query 同 stem 页或 centralized 他仓页面借用算子。

## 核心内容

B4 使用内部 write_guard，默认 observe，可显式 enforce。分类 pending、planned_not_pending、unplanned、delete_only、unavailable；pending 包含 failed/skipped，delete 不授权重建。结构算子优先匹配自身 page_key，旧算子只匹配 canonical module 路径；target 也受当前仓分区约束。计划须通过 schema_version 与 plan_hash 校验，page_key: null 是合法缺省。

## 原因与边界

change_plan 是操作簿记而非安全边界，精确 target 是显式例外；审计写失败只能告警，不能改变 enforce 裁决。路径逃逸仍先由 page_router 拦截，审计不进入 plan_hash。
