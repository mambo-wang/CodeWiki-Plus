## 背景

ADR-0020 的 P1-2 修两个生成缺陷，两处都不报错、只静静地少内容：

1. `caw_backend.py` / `pydantic_ai_backend.py` 只要 `overview.md` 存在就让所有模块 agent 提前返回；
2. `documentation_generator.py` 对单模块异常只 `continue`，随后照常写 overview 与 `metadata.json`，外部看到“成功”。

## 核心内容（五条约束）

1. **跳过粒度只能是页面**。`overview.md` 存在只说明 overview 页存在，不能推出任何模块页存在。两个 backend 共用一个 `module_page_present(working_dir, module_name)` 判定；父模块页同理，`generate_parent_module_docs` 只按自己的 `<parent>.md` 跳过。
2. **失败要聚合后抛，不是逐条 warn**。循环里收集 `(module_key, error)` 并继续跑其余模块与 overview，最后抛 `ModuleGenerationError`；CLI 适配器把它包成 `APIError`，退出码非 0。这样既保留部分产出，又不给“成功”假象。
3. **失败时仍写 `metadata.json`**。已落盘的页面需要被登记（metadata 是摘要，不是成功证书）；`run()` 与 CLI 适配器都用 `try/finally` 保证。
4. **legacy 管线只注解已有账本，不创建不关闭**。`.meta/job.json` 的创建与关闭归 MCP 路径；legacy 在有账本时追加页面写入与 `degraded`（`module_failed` / `overview_failed`）并置 `phase=degraded`。否则一次 `codewiki generate` 会把 MCP 的 `partial` 状态覆盖成 `done`。无账本时这些调用是 no-op。
5. **“agent 返回” ≠ “页面存在”**。标 `mark_page_written` 前先 `os.path.exists`；否则静默不写文件的 agent 会被记成已写，续跑视图里缺页消失。

## 影响范围

`codewiki/src/be/backend.py`（`module_page_present`）、`caw_backend.py`、`pydantic_ai_backend.py`、`documentation_generator.py`（`ModuleGenerationError` + 账本注解）、`cli/adapters/doc_generator.py`。

## 验证

`tests/test_generation_gaps.py`：overview 存在时缺页仍被生成、父模块页不被 overview 短路、失败模块聚合并抛错、metadata 在失败前写出、无账本时不创建 `job.json`、失败写 `phase=degraded` 且 missing 正确、两个 backend 不再提前返回。
