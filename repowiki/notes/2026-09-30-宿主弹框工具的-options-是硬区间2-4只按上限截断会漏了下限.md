## 结论
宿主结构化提问工具的 options 是**区间约束**（Qoder `AskUserQuestion`：单题 2-4 个，越界直接报错），不是只有上限。为「任务太多装不下」做截断时，只算上限会把下界当成理所当然。

## 踩坑
任务关联弹框改成 capped 档后，选项构成写成「最近至多 3 个任务 + 跳过」，并靠「其他」自由输入承接新建/选已存任务。看起来永远合法，但 `active == []`（新仓库/刚克隆）时 options 退化为 1 项「跳过」→ 调用直接失败，任务关联流程在**最应该引导用户建任务的那一次**并不可用；同时另一句「进行中共 0 个任务，未进选项的写进正文任务清单」无条件发出，而该清单小节只在 `if rest:` 里才渲染，指代悬空。

## 做法
1. 截断策略要同时证明 `min <= n <= max` 对任意输入成立：有空位（`len(shown)+1 < cap`）就补一个显式「新建任务」选项，兼顾了发现性（新建可点不必只靠「其他」）。
2. 任何引用「下面某个小节」的文案，必须和该小节的渲染条件共用同一个 `if`。
3. label 截断防撞：中文长标题前 12 字相同时，换用 task_id 也撞（id 常由标题生成）；label 无硬字符上限（只有 header 限 12），所以撞车时逐步延长比换源更可靠。
4. 测试要按输入区间边界取档（0/1/2/3/4/9），只测「典型大值」会整档漏掉越界情形——本次就是 5 个任务的用例全绿而 0 个任务仍碎。
