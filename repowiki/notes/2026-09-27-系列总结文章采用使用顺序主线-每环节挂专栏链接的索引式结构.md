## Background
2026-09-27 重写 CodeWiki 使用全景文章时，用户要求根据 README 里列的 12 篇公众号文章丰富内容。

## Decision
采用「使用顺序主线 + 每环节挂专栏文章链接」的结构：文章按「问题背景 → 安装初始化 → 按需生成 Wiki → 日常开发参与 → 知识写入与可信度 → 任务管理 → 团队化飞轮 → 最佳实践清单」组织，每个环节末尾挂对应公众号文章链接，深度内容指向原文。这样总结篇既是独立可读的上手指南，又是整个系列的索引。

## 边界（用户确认的前提）
助手无法抓取微信公众号链接正文，深度内容只能基于标题主题 + README 对应章节展开，每节末尾放原文链接供读者跳转。用户确认此方案后执行。

## Rationale
总结篇若复述全部专栏内容会冗长且无法维护；挂链接的索引式结构让每层内容单点维护，总结篇只负责导航与判断标准（何时启用哪层能力）。
