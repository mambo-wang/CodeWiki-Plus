## Background

任务记忆免确认压缩改为「主 Agent 异步 spawn 子代理」后，get_task_context 在 red 档携带 `compaction_action` 派发指令（`codewiki/mcp/tools/task_manager.py` `_compaction_action`）。OCR 评审发现该指令里的示例调用只写 `compact_task_memories(mode="prepare", task_id=...)`，不带 `repo_path`，而 `handle_compact_task_memories` 在无 session 且无 repo_path 时直接返回 `repo_path is required`。子代理是全新上下文，唯一信息来源就是这条指令 → 按字面执行必失败。本轮派发压缩时我是手工往子代理 prompt 里补的 repo_path，属于同一个坑的旁证。

## Lesson

**派发给子代理的指令必须自包含：把执行所需的全部寻址/标识参数内联到指令文本里，不能假设子代理继承主 Agent 的会话态。**

具体口径：
- 指令由工具返回时，它拥有调用方上下文（arguments 里的 repo_path、session.repo_path），就应该把这些值**烘进指令字符串**，而不是只写参数名让主 Agent 自己填；
- 主 Agent “会自己补”不是设计保障：它会漏、会填错仓库，且这类失败只在子代理跑完才暴露（异步不阻塞）；
- 测试要钉“指令里带不带参数值”，而不是只钉“有没有这个字段”：`assert 'mode="prepare", repo_path=' in action["dispatch"]`。

## 反模式

- 工具返回一段给另一个执行体用的自然语言菜谱，菜谱里的工具调用只给部分参数
- 只断言指令文本包含工具名/模式名，不断言寻址参数
