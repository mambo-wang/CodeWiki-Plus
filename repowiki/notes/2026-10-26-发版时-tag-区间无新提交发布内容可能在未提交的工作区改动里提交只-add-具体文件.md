## Background

执行 codewiki 5.16.2 发版（windows-python-release 流程）时，`git log v5.16.1..HEAD` 显示无新提交，但本次发布内容真实存在——全部是工作区未提交的改动：`codewiki/mcp/_ide_hook.py` 的 CodeBuddy index 展开竞态容忍（SessionEnd vs Finalize race 等待消息文件落盘）+ hook 捕获失败可观测性日志，配套 `tests/test_ide_hook_capture.py`。

## 正确做法

- tag 区间无新提交 ≠ 没有发布内容：先 `git status --short` + `git diff --stat` 核对工作区未提交改动，据其内容判断 patch/minor bump（本次属 fix → patch bump 5.16.1 → 5.16.2）。
- 版本同步四处：`pyproject.toml` 与 `codewiki/__init__.py` 手改，`uv.lock` 用 `uv lock` 刷新，`server.py` 由 `__version__` 注入无需改。
- 提交纪律：只 add 具体文件，fix 改动一个 commit、版本 bump 一个 commit；工作区混着的 repowiki 产物等非发布文件不入库（多会话并行时的 pathspec 隔离细节见 `notes/2026-10-21-共享工作区多会话并行时提交必须用显式-pathspec禁止-git-add--a-扫入并行会话的改动.md`，此处不重复）。
- 发布闸门顺序：聚焦测试（改动模块）→ ruff check/format → 全量测试（本次 1299 passed / 3 skipped）→ 提交推送。

## Rationale

「tag 区间无提交」容易被误判为无事可发，实际发布内容可能尚未提交；发版会话中工作区常混有 repowiki 产物等非发布文件，整仓 add 会误入库。此场景每次发版都可能复现，值得持久化。
