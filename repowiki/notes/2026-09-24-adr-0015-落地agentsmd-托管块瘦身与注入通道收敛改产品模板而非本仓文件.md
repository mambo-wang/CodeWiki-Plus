## Background

竞品调研（project-cairn/openwiki/better-harness/caveman/teamai-cli/claude-mem/hindsight/letta-code）发现本仓 AGENTS.md 超重（数百行），且 task-memory 协议存在 AGENTS.md 块与 SessionStart hook system_reminder 的双通道重复注入，违反单点收敛。grill 两轮（Q1-Q12）拍板后实施，提交 cb305c7。

## Decision

优化对象是**产品模板**（`locales/zh.yaml`/`en.yaml`、`prompts.py`），不是本仓 AGENTS.md——三个托管块都是生成物，改模板即改所有下游用户仓库。

1. **D1 CodeWiki 块 89→45 行**：保留采纳声明、标注依据、语言闸门（行为闭环关键，采纳计数驱动检索排序）；纠正识别三步流程并入使用建议第 3 条；归档示例 JSON 删除、指向 `get_prompt(name="ingend-note")`（实际为 ingest-note）；路由表压成单行。
2. **D2 `_TASK_MEMORY_AGENTS_SECTION` 40→8 行指针式**：hook 注入优先，未注入时按 `get_prompt("task-workflow")` 执行——消除与 SessionStart hook 的双通道重复。放弃「hook 感知渲染」（读 settings.json 判断接线状态太脆、标记文件会失配），退到「无条件渲染指针版」，符合「显式优于缓存」。
3. **D3 手写节外移**：Team memory fusion 20 行实现细节移入 `repowiki/wiki/team-memory-fusion.md`，AGENTS.md 留一行链接。
4. **本仓刷新用产品渲染器**：直接调 `_build_section` + `_upsert_marked_section` / `upsert_agents_section` 刷新本仓两块，保证与模板逐字节一致——手写 replace 多次笔误后改用此法。本仓 AGENTS.md 163→97 行。

## Rationale

「只删与 hook 重复的，留唯一的」是收敛边界；ACTIVE-SETTLE 块无 hook 对应物（停顿点判据、双写入路径、ADR-0009 supersedes 规则的唯一载体），刻意保留。存量仓库迁移零成本：`_upsert_marked_section` 是标记对标记整块替换（`agents_md.py:139`），下次运行自动升级。`en.yaml` 与 zh 结构完全对齐（六节同构），必须同步改避免中英文模板永久漂移。

## 明确不借

claude-mem 六事件采集（噪音）、内联 bash 路径解析、letta commit-on-write（模型相反）、原生 `async:true`（需真机验证 CodeBuddy 支持，现有 detached 方案已工作，deferred）。golden fixture 测试（D5）deferred 到下次动 `ide_config.py` 前补。与 `2026-09-20-竞品-hookagentsmd-机制盘点路由层极简化是共识多事件采集是反面教材.md` 互补：该笔记保留调研原始事实，本笔记记录落地决策。
