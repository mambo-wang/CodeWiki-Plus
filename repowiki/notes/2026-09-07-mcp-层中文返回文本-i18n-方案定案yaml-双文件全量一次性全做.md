## 背景

用户提出 `codewiki/mcp/prompts.py` 里 22 个 prompt 的 title/description 是硬编码中文，希望按系统语言或配置语言返回对应语言。审计后发现中文不止元数据，还包括 prompt 正文（约 1250 行）、`_SERVER_INSTRUCTIONS`（57 行）、`resources.py` 的 `prompts/catalog`（约 92 行）、工具层少量散点，以及写入用户仓库的落盘产物（AGENTS.md 约定块、index.md、schema.yaml 模板）。**工具 schema description 与错误消息经审计全部是英文**，不在本次范围内。

## 定案（用户逐项拍板）

1. **资源格式 YAML 双文件全量**：`codewiki/mcp/locales/zh.yaml`（唯一事实源）+ `en.yaml`（全量覆盖），代码内不留中文文案，经 `codewiki/mcp/i18n.py` 的 `t(key, **fmt)` 按点分 key 取值。选 YAML 而非 properties/JSON 的理由：PyYAML 已是硬依赖（`pyproject.toml:53`），支持层级、块文本、注释；properties 在 Python 无内置解析、无层级、多行 description 要转义续行。
2. **一次性全做**（Q6 选 A）：机制 + 约 1500 行英文内容一次合入，不切批次。
3. **不做运行时回退**（Q3 选不回退）：缺 key 时返回哨兵而非落回中文，靠发版前的「`zh.yaml` key 集 ⊆ `en.yaml` key 集」一致性测试暴露，暴露后补文案。
4. **范围含落盘产物**（Q7 选纳入）：`tools/agents_md.py`、`wiki_index.py`、`reading_guide.py`、`schema_generator.py` 的产出语言跟随 server 运行时语言。
5. **顺带去硬编码漂移**（R3 选 b）：`prompts/catalog` 改为从 `list_prompts` 注册表派生、`tool_count` 改为运行时计数、instructions 里的数量改为真实值。

## 理由

- 语言只能在 server 进程启动时确定一次（MCP 协议无 per-request 语言协商），因此「按语言取词」本质是启动期常量选择，不需要复杂运行时机制。
- 用户选资源文件的诉求是「便于管理」；半内建半文件会让 zh/en 两处维护同一批文案，比全量搬更糟。
