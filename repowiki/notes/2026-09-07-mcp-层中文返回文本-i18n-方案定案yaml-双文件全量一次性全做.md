## 背景

用户提出 `codewiki/mcp/prompts.py` 里 22 个 prompt 的 title/description 是硬编码中文，希望按系统语言或配置语言返回对应语言。审计后发现中文不止元数据，还包括 prompt 正文（约 1250 行）、`_SERVER_INSTRUCTIONS`（57 行）、`resources.py` 的 `prompts/catalog`（约 92 行）、工具层少量散点，以及写入用户仓库的落盘产物（AGENTS.md 约定块、index.md、schema.yaml 模板）。**工具 schema description 与错误消息经审计全部是英文**，不在本次范围内。

## 定案（用户逐项拍板）

1. **资源格式 YAML 双文件全量**：`codewiki/mcp/locales/zh.yaml`（唯一事实源）+ `en.yaml`（全量覆盖），代码内不留中文文案，经 `codewiki/mcp/i18n.py` 的 `t(key, **fmt)` 按点分 key 取值。选 YAML 而非 properties/JSON 的理由：PyYAML 已是硬依赖（`pyproject.toml:53`），支持层级、块文本、注释；properties 在 Python 无内置解析、无层级、多行 description 要转义续行。
2. **一次性全做**（Q6 选 A）：机制 + 约 1500 行英文内容一次合入，不切批次。
3. **不做运行时回退**（Q3 选不回退）：缺 key 时返回哨兵而非落回中文，靠发版前的「`zh.yaml` key 集 ⊆ `en.yaml` key 集」一致性测试暴露，暴露后补文案。
4. **范围含落盘产物**（Q7 选纳入）：`tools/agents_md.py`、`wiki_index.py`、`reading_guide.py`、`schema_generator.py` 的产出语言跟随 server 运行时语言。
5. **顺带去硬编码漂移**（R3 选 b）：`prompts/catalog` 改为从 `list_prompts` 注册表派生、`tool_count` 改为运行时计数、instructions 里的数量改为真实值。

## 理由

- 语言只能在 server 进程启动时确定一次（MCP 协议无 per-request 语言协商），因此「按语言取词」本质是启动期常量选择，不需要复杂运行时机制。
- 用户选资源文件的诉求是「便于管理」；半内建半文件会让 zh/en 两处维护同一批文案，比全量搬更糟。

## 范围修订（方案 E，2026-09-08）

> 本节修订上文「定案」第 2 条（一次性全做）：prompt 正文退出翻译范围。

### 修订内容

1. **22 篇工作流正文停止翻译，维持中文单份**（已翻的 4 篇回退）。理由不是「用户看不到」，而是**读者是 LLM，跨语言理解无损**；产出语言另由约束控制。
2. **产出语言闸门下沉到项目根 `AGENTS.md` 约定块**（`codewiki/mcp/tools/agents_md.py`，各 IDE 都稳定加载项目根 AGENTS.md），`server.instructions` 里再加一句「语言」小节作为双保险，并显式写明「指引语言 ≠ 产出语言」，避免 Agent 模仿中文正文。
3. 元数据层（22 条 title/description/参数说明）、resources、`server.instructions`、工具层散点、落盘产物（AGENTS.md 约定块、schema.yaml、review_checklist、index.md、阅读指南）**仍做双语**——这些才是人类可见的部分。
4. 上文第 4 条（范围含落盘产物）与第 5 条（顺带去硬编码漂移）不变；存量中文产物仍不追溯重写，只影响新生成/整体重写路径。

### 理由（三个决定性事实）

- **竞品做法**：Context7（Upstash，MCP 领域标杆）的 MCP 层零 i18n——暴露给 LLM 的 `resolve-library-id` / `query-docs` 工具名与参数说明全是英文一份；它的 `i18n/README.{zh-CN,zh-TW,ja,ko,es,fr,de,ru,ar…}` 共 20 种语言翻译的是**人类读的文档**；想约束行为时让用户自己写宿主规则文件（Cursor `Settings > Rules`、Claude Code `CLAUDE.md`）。即「给机器的文案英文单份、给人的文档多语言、行为约定交给宿主规则文件」。
- **MCP instructions 不可靠**：lifecycle 规范里 `instructions` 只有一句 `"instructions": "Optional instructions for the client"`，**没有任何 MUST/SHOULD 的注入要求**，客户端怎么处理由实现自定（Claude Desktop 长期有忽略 server instructions 的已知问题）。把语言约束寄托在它上面是赌客户端实现。
- **指令语言会传染产出语言**：prompt 正文不是说明书，是 Agent 的执行脚本——`write_doc_file` 写出的 wiki 页面、`ingest_note` 存的笔记、落盘的 AGENTS.md/schema.yaml，语言都跟着指令走。正文改英文单版等于把中文用户的产出一起换成英文（中文项目里长出英文 wiki）。折中方案（正文英文单版、产物仍 i18n）会造成「读英文指令却在中文仓库写中文 AGENTS.md」的长期不一致，不采用。

### 边界

- AGENTS.md 只在 `init_wiki` 过的仓库存在。
- `schema.yaml` 等模板文案由 Python 写死、不是 LLM 产出，不受语言约束影响，仍必须 i18n，省不掉。
