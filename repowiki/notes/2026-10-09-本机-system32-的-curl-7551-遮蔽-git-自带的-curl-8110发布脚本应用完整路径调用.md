## Background
v5.14.1 发布用 Python 构造 multipart body + curl.exe --data-binary 绕法成功后，用户追问 curl.exe 能否升级。实测发现本机存在两个 curl.exe：C:\Windows\System32\curl.exe（系统自带 7.55.1）和 C:\Program Files\Git\mingw64\bin\curl.exe（Git for Windows 附带 8.11.0）。系统 PATH 中 System32 排在 Git mingw64 之前，导致 curl.exe 总是解析到旧版。

## 结论
无需升级系统 curl：发布脚本直接写完整路径 C:\Program Files\Git\mingw64\bin\curl.exe（curl 8.11.0 ≥ 7.84）即可使用 -K 配置文件的 form-string/form-file 长选项，走标准表单上传，免去手工构造 multipart body 的绕法。本机无 winget/scoop/choco，升级系统 curl 成本高且无必要。

## Rationale
「工具版本太老」的真实根因常是 PATH 解析而非缺装；本机已有所需版本时改完整路径调用是最小成本的永久解法，避免每次发布重复绕法。该结论在对话中经 curl --version 实测确认。

## 适用范围
本仓发布脚本及任何依赖较新 curl 特性的 Windows 本机脚本。
