## Background

Qoder 宿主工具目录中的 codewiki 可能显示 disconnected、toolCount=0，但 project/local 配置仍有效；对当前会话执行 enable 也可能返回 sessionApplied=false。宿主未挂载工具不能直接推断 MCP 服务端故障。

## 正确做法

1. 读取宿主实际使用的同一组 command、args、cwd 和非敏感 env，不另起一套服务参数。
2. 用正式 MCP ClientSession + StdioServerParameters 启动 server，先 initialize，再调用 list_tools 或一个只读 get_prompt；真实握手和工具返回才能证明服务端、dispatch 与 schema 正常。
3. 本地 stdio 探活客户端清除 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY 及对应小写变量，并设置 CODEWIKI_NO_AUTOUPDATE=1；需要仓库级索引时显式设置 CODEWIKI_HOME。
4. 临时客户端用 start_new_session=True 隔离 server 进程组，结束时关闭 stdin 并终止整个进程组；不要先关闭 stdout 再阻塞读取子进程 stderr，否则工具结果已返回但客户端仍可能挂住。

## Rationale

这样能把「宿主连接器未挂载」与「服务端不可用」分开判断，同时保留正式 MCP dispatch/schema 校验，避免直连 handler 绕过协议并遗留后台进程或暂存文件。

## Root cause

当前会话的工具目录只暴露已挂载连接，重新 enable 未必能热应用到当前会话；server 或其子进程未完整退出时，stdio 生命周期会继续悬挂。

## 边界与恢复

若 initialize 或正式工具调用本身失败，应停止并报告原始错误，不反复重试、不改连接器配置，也不改用 handle_* 直连。客户端清理只影响本次探活进程，不修改用户全局代理或 MCP 配置。
