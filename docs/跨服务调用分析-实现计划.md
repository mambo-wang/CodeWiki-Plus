### 一、总体架构

借鉴 CBM 的核心思想：**不直接匹配函数调用，而是通过协议无关的 Route 节点间接建立跨服务关联。**

```
┌─────────────────────────────────────────────────────────────┐
│                   analyze_workspace                         │
│                                                             │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐               │
│  │ Repo A   │   │ Repo B   │   │ Repo C   │               │
│  │ analyze_ │   │ analyze_ │   │ analyze_ │               │
│  │ repo     │   │ repo     │   │ repo     │               │
│  └────┬─────┘   └────┬─────┘   └────┬─────┘               │
│       │               │               │                     │
│       ▼               ▼               ▼                     │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐               │
│  │ Route    │   │ Route    │   │ Route    │               │
│  │ Extract  │   │ Extract  │   │ Extract  │  ← NEW PASS   │
│  │ (SQLite) │   │ (SQLite) │   │ (SQLite) │               │
│  └────┬─────┘   └────┬─────┘   └────┬─────┘               │
│       │               │               │                     │
│       └───────────────┼───────────────┘                     │
│                       ▼                                     │
│              ┌─────────────────┐                            │
│              │ CrossService    │  ← NEW ENGINE              │
│              │ Matcher         │                            │
│              │ (4-phase match) │                            │
│              └────────┬────────┘                            │
│                       ▼                                     │
│              ┌─────────────────┐                            │
│              │ Workspace       │                            │
│              │ Overview.md     │  ← 自动填充跨服务关系       │
│              │ + Mermaid 拓扑  │                            │
│              └─────────────────┘                            │
└─────────────────────────────────────────────────────────────┘
```

数据流：每个 repo 的 `analyze_repo` 在 AST 解析管线中新增 Route 提取 pass → Route 节点持久化到该 repo 的 SQLite 缓存 → `analyze_workspace` 汇总所有 repo 的 Route → `CrossServiceMatcher` 执行四阶段匹配 → 匹配结果渲染为 Mermaid 拓扑图 + Markdown 表格写入 overview.md。

```python
class RouteProtocol(str, Enum):
    HTTP = "http"
    GRPC = "grpc"        # Phase 2
    GRAPHQL = "graphql"   # Phase 2
    MQ = "mq"             # Phase 2

class RouteRole(str, Enum):
    SERVER = "server"     # 服务端路由处理器
    CLIENT = "client"     # 客户端 HTTP 调用

class RouteNode(BaseModel):
    route_key: str              # "__route__POST__/api/orders/{}"
    protocol: RouteProtocol
    method: Optional[str]       # GET, POST, etc.
    path: str                   # 规范化后的路径
    role: RouteRole
    component_id: str           # 关联的 Node ID
    repo_name: str
    file_path: str
    line_number: int = 0
    framework: Optional[str] = None  # fastapi, spring, express, etc.

class CrossServiceLink(BaseModel):
    route_key: str
    protocol: RouteProtocol
    method: Optional[str]
    path: str
    client_repo: str
    client_component_id: str
    server_repo: str
    server_component_id: str
    confidence: float = 1.0

class WorkspaceTopology(BaseModel):
    repos: List[str]
    routes: List[RouteNode]
    links: List[CrossServiceLink]
    unmatched_routes: List[RouteNode]
```

#### 2.2 路径规范化工具

**新建文件**：`codewiki/src/be/dependency_analyzer/utils/path_canonicalizer.py`

移植 CBM 的 `cbm_route_canon_path()` 逻辑，约 50 行：

```python
def canonicalize_path(path: str) -> str:
    """统一路径参数语法：:id, {id}, <id>, ${...} → {}"""
    result = re.sub(r':([a-zA-Z_]\w*)', '{}', path)
    result = re.sub(r'\{[^}]+\}', '{}', result)
    result = re.sub(r'<[^>]+>', '{}', result)
    result = re.sub(r'\$\{[^}]+\}', '{}', result)
    if len(result) > 1 and result.endswith('/'):
        result = result.rstrip('/')
    return result

def make_route_key(method: str, path: str) -> str:
    return f"__route__{method.upper()}__{canonicalize_path(path)}"
```

#### 2.3 Route 提取器（按语言分模块）

**新建目录**：`codewiki/src/be/dependency_analyzer/analyzers/route_extractors/`

每个提取器是一个独立模块，接收文件内容，返回 `List[RouteNode]`。作为现有语言分析器的 **后处理 pass** 运行，不侵入现有解析逻辑。

##### Python Route 提取器 (`python_routes.py`)

用 Python `ast` 模块解析（与现有 python_analyzer 复用同一解析器）。

检测模式：

| 类型 | 模式 | 示例 |
|------|------|------|
| Server | `@app.get("/path")` | FastAPI |
| Server | `@app.route("/path", methods=["GET"])` | Flask |
| Server | `@router.post("/path")` | FastAPI APIRouter |
| Server | `path("route/", view)` | Django urlpatterns |
| Client | `requests.get("http://host/path")` | requests |
| Client | `httpx.post(url, json=...)` | httpx |
| Client | `session.get("/api/...")` | aiohttp |

注入点：在 `CallGraphAnalyzer._analyze_code_file()` 末尾，对 Python 文件额外调用 `extract_python_routes()`。

关键 AST 模式：
```python
# 服务端：decorator_list 中的 Call 节点
# decorator.func.attr == "get"/"post"/"put"/"delete"/"route"
# decorator.args[0] 为字符串字面量 → URL path

# 客户端：body 中的 Call 节点
# func.value.id == "requests" and func.attr in {"get","post",...}
# func.args[0] 为字符串字面量 → URL
```

##### Java Route 提取器 (`java_routes.py`)

用 Tree-sitter Java（与现有 java_analyzer 复用同一解析器）。

检测模式：

| 类型 | 模式 | 示例 |
|------|------|------|
| Server | `@GetMapping("/path")` | Spring MVC |
| Server | `@RequestMapping(value="/path", method=...)` | Spring MVC |
| Server | `@GET @Path("/path")` | JAX-RS |
| Client | `restTemplate.getForObject("url", ...)` | RestTemplate |
| Client | `webClient.get().uri("/path")` | WebClient |
| Client | `@FeignClient` 接口方法 | Feign |

注入点：在 Java 分析器的 `_extract_nodes` 中，遇到 `method_declaration` 时检查 annotation 子节点。

##### TypeScript/JavaScript Route 提取器 (`js_routes.py`)

| 类型 | 模式 | 示例 |
|------|------|------|
| Server | `app.get("/path", handler)` | Express |
| Server | `router.post("/path", handler)` | Express Router |
| Server | `@Get("/path")` / `@Controller()` | NestJS |
| Client | `axios.get("url")` | Axios |
| Client | `fetch("/api/...")` | Fetch API |

##### Go Route 提取器 (`go_routes.py`)

| 类型 | 模式 | 示例 |

#### 2.6 跨服务匹配引擎

**新建文件**：`codewiki/src/be/dependency_analyzer/analysis/cross_service_matcher.py`

```python
class CrossServiceMatcher:
    """四阶段跨仓库 Route 匹配引擎"""

    def add_repo_routes(self, repo_name, routes):
        """累积一个仓库的 Route 节点"""

    def match(self) -> WorkspaceTopology:
        """执行匹配：
        Phase 1: HTTP 路由匹配（精确 + 模糊模板降级）
        Phase 2: MQ 生产者/消费者（Phase 2 实现）
        Phase 3: Channel EMITS/LISTENS_ON（Phase 2 实现）
        Phase 4: gRPC/GraphQL/tRPC（Phase 2 实现）
        """

    def _match_http_routes(self):
        """核心匹配逻辑：
        1. 按 route_key 建立 server 索引
        2. 遍历 client routes，查找匹配的 server
        3. 精确匹配失败 → 模糊模板匹配（逐段比较）
        4. 跳过同仓库匹配（intra-repo 不是 cross-service）
        5. 生成 CrossServiceLink
        """
```

模糊模板匹配算法（移植自 CBM `cr_path_matches_template`）：

```python
def path_matches_template(concrete: str, template: str) -> bool:
    """逐段比较：{} 段匹配任意非空段"""
    c_segs = [s for s in concrete.split('/') if s]
    t_segs = [s for s in template.split('/') if s]
    if len(c_segs) != len(t_segs):
        return False
    for c, t in zip(c_segs, t_segs):
        if t == '{}':
            if not c:
                return False
        elif c != t:
            return False
    return True
```

### 七、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| Routes 存储方式 | 独立集合，不嵌入 Node | 避免膨胀 Node 模型，查询独立 |
| Route 提取时机 | 文件分析的后处理 pass | 最小侵入，不改现有分析器核心逻辑 |
| 匹配时机 | workspace 级别（analyze_workspace 时） | 单 repo 分析时不知道其他 repo 的存在 |
| 匹配结果存储 | workspace session 的 JSON + SQLite | 轻量，不改单 repo DB schema |
| Route key 格式 | `__route__METHOD__path` | 与 CBM 兼容，未来可互操作 |
| 模糊匹配 | 逐段模板匹配（移植 CBM 算法） | 处理具体路径 vs 模板路径 |
| 语言优先级 | Python → Java → TS/JS → Go | 匹配 CodeWiki-CN 用户群 |
| 优雅降级 | CBM 可用时委托，不可用时本地匹配 | 保持零外部依赖的核心价值 |
