# 任务记忆退役与写入检查设计方案

> 日期：2026-09-18 · 状态：定稿待实施 · 归属任务：统一知识存储层（KnowledgeStore 动词式门面）
> 决策方式：grill-with-docs 两轮（Q1-Q11 全按推荐定案）；ADR-0009 已落
> （`docs/adr/0009-task-memory-supersede-and-write-check.md`）
> 术语：「退役（retired）」「写入检查（write check）」见 CONTEXT.md。

## 一、问题定义（现状事实，2026-09-18 实读）

任务记忆（`tasks/<task_id>/memories/<user_id>.md`）是 append-only 的
`### YYYY-MM-DD HH:MM` 时间戳头条目（`task_manager.py:154`），写入路径两条：
主动沉淀 `add_task_memory`（`task_manager.py:634-663`）与蒸馏直写
`append_task_memories_direct`（`task_manager.py:360-387`）。两个结构性缺口：

1. **无失效语义**：「下一步做 X」后来改成 Y，两条都在 hot 层被
   `get_task_context` 注入，过时结论与现行结论并列，Agent 无从分辨。
2. **无写入质量门**：追加无去重、无条数限流（ADR-0008 已确认「任务记忆追加
   无去重」），停顿点判断靠 Agent 自觉，40 条/24KB 压缩阈值被流水账消耗。

压缩时机为**读取驱动**：`get_task_context` 经 `_compaction_needed`
（`task_manager.py:204-213`，阈值 `_COMPACTION_THRESHOLD_COUNT=40` /
`_COMPACTION_THRESHOLD_BYTES=24KB`、keep 窗口 `_COMPACTION_KEEP`）判定，
超线则内联 `compaction_work`（`task_manager.py:710-725`）由本会话 Agent
顺手 submit。写入路径不触发压缩。**2026-10-09 修订**：该内联载荷已改为轻派发指令
`compaction_action`，执行者改为异步子代理（详见《任务记忆检索与自动压缩设计》D6）。存储格式维持 Markdown（ADR-0001）。

## 二、决策（Q1-Q11）

### D1 范围（Q1）

| 项 | 处置 |
|---|---|
| P0-1 supersede 失效语义 | **本期做** |
| P0-2 写入质量门（纪律 + 去重 + 软上限） | **本期做** |
| P2-5 compaction_due 红橙黄分级 | **本期做**（顺手，布尔改三值） |
| P2-6 蒸馏 prepare 修订提示 | **本期做**（纯提示增强） |
| P1-3 Handoff 任务现状快照 | **立项独立排期**（powercontext 候选 1 落法已有，不混入本期） |
| P1-4 蒸馏事件流 + 整数 ID 映射 | **砍掉**（与 consolidate 收益重叠，改动面不值） |

### D2 supersede 引用方式（Q2）：惰性条目 ID

- **新条目**：写入时生成短 ID（`#` + 4 位 base36，如 `#a3f2`），写在时间戳头
  行尾（`### 2026-09-18 14:30 #a3f2`）。
- **存量条目**：不回写文件。`get_task_context` 注入时按文件内出现顺序补
  `#e01`、`#e02`… 序号（exhaustive 前缀区分存量惰性号与新写入持久号）。
- **supersede 匹配**：单 ref 匹配——`supersedes` 传持久 ID（`#a3f2`）或注入时
  可见的惰性序号（`#e03`），命中唯一条目即生效；ref 无命中或命中已退役条目
  返回 error（不静默，Doctrine「不静默失败」）。
  （实施简化：定稿时的「ID+时间戳双匹配」收敛为单 ref 匹配——ref 本身已含
  定位信息，双匹配在同分钟撞车场景外无额外收益。）
- 否决项：纯时间戳定位（同分钟撞车）、内容前缀匹配（改写即静默失败）。

### D3 写入去重（Q3）：difflib 确定性比对

- 新条目与比对范围（D5）内条目做 `difflib.SequenceMatcher` 比对，
  `ratio > 0.85` → **拒绝写入**，返回最相似条目原文 + 提示（改用 supersede
  推翻，或合并改写后重试）。
- 阈值 0.85 偏保守：宁可漏放不可误拒（fail-open）。零 LLM、零依赖、确定性。
- 实施防御：比对前剥离条目头（时间戳/ID 行）与摘要标题行——头部按构造不同，
  会稀释真重复的 ratio；短文本（<20 字符）豁免——一字之差即高 ratio，无有效
  信号（fail-open）。
- 否决项：纯协议纪律（现状已被证明不够）、精确哈希（自由文本形同虚设）。

### D4 软上限超限行为（Q4 + Q7 + Q10）

- **计数口径（Q7）**：以「上次压缩」为窗口分界——压缩 submit 后清零，压缩前
  累计。纯文件时间戳可算（压缩会重写文件，摘要段之后的条目即窗口内条目），
  零新增状态文件。
- **超限行为（Q4）**：警告放行 + hint，不硬拒（fail-open 边界；补录多条历史
  决策是合理场景）。
- **写侧信号（Q10）**：`add_task_memory` 返回值携带 `hot_entries: "43/40"`
  计数（写入检查读文件时顺手可得，零额外 IO），超阈值附
  `hint: 建议压缩`。压缩执行仍归读侧 `compaction_action` 驱动，写侧只报数不干活。

### D5 去重比对范围（Q8）

hot 层尾部 10 条 + **压缩摘要段**。只比尾部会漏「重复摘要已覆盖的结论」；
全比会误拒「与将淘汰旧条目相似」的新写入。摘要段**逐份独立比对**（own 与
legacy 各算各的 ratio）——拼接成单一长文本会稀释相似度，让「重复摘要已覆盖
的结论」漏放。

### D6 supersede 作用域（Q5）：仅本人文件

跨用户推翻不可实现（注入侧按 `_current_user_id()` 过滤，Agent 无从得知他人
条目）。多人协作的「共同结论被推翻」归任务描述与笔记通道。

### D7 退役标记形态（Q11）：单行 markdown 标记

在被推翻条目的时间戳头行下插入一行：

```
> [superseded 2026-09-18 by #a3f2]
```

- 与 `_ENTRY_TS_RE` 逐行扫描惯例兼容（新增同风格正则
  `^> \[superseded .+ by (#\w+)\]`）。
- 改写走既有 `locked_rmw` 原子读改写（对齐 `task_manager.py:1023` archive
  写惯例）。
- **单向引用**：只在被推翻方标记，新条目不回写——对齐 ADR-0007「双向引用
  易漂移」教训。
- 注入侧（`get_task_context`）与检索侧（`search_task_memories`）跳过带标记
  条目；检索命中 archive 中的退役条目时标注 `superseded: true`。

### D8 superseded 条目的压缩去向（Q6）：优先压缩

压缩候选排序：superseded 条目最先摘出（已被推翻，保留全文价值最低），然后
正常旧条目。archive 全文保留，可逆，不违反退役纪律。

### D9 压缩分级（Q9.5）：黄/橙/红三值

`compaction_due: bool` 升级为 `compaction_level: "green"|"yellow"|"orange"|"red"`：

| 级 | 条数 | 字节 | 行为 |
|---|---|---|---|
| green | <30 | <18KB | 无信号 |
| yellow | ≥30 | ≥18KB | 提示「接近阈值，可顺手压缩」 |
| orange | ≥35 | ≥21KB | 建议压缩 |
| red | ≥40 | ≥24KB | 既有 `compaction_action` 派发驱动（2026-10-09 起：轻指令 + 异步子代理） |

双维取 max（任一维触线即升级）；分界线按既有阈值 75%/87.5%/100% 内插，不引入
新判据。`compaction_due` 保留为 red 的布尔别名（向后兼容，调用方无感迁移）。

### D10 蒸馏 prepare 修订提示（Q9）

`distill_conversation(mode="prepare")` 响应的提示段增加一句：既有笔记若被本次
对话推翻/补充，可在提取结果中标注建议修订（引用笔记文件名）。零机制改动，
纯提示增强，为将来事件流留接口。

### D11 协议块纪律（P0-2 的 prompt 侧）

AGENTS.md 主动沉淀协议块（CODEWIKI-ACTIVE-SETTLE）补一条写入标准：
「只记会改变下一步行动的进展/决策/约束，纯执行过程不记」——powercontext
抽取标准（「只保留会改变未来工作的信息」）的移植。与工程侧写入检查互补：
prompt 防自觉缺失，工程兜底。

## 三、验收链

1. **supersede 基本流**：`add_task_memory(content=..., supersedes="#e01")` →
   被引用条目头下出现 `> [superseded 日期 by #新ID]` → `get_task_context`
   不再注入该条目 → `search_task_memories` 命中时标注 superseded。
2. **坏 ref 显式报错**：`supersedes` 无命中（拼错/已被压缩摘走）或命中已
   退役条目 → 返回 error，不静默标记，且**不追加新条目**（先验证 ref 再落盘，
   不留无主孤儿条目）。
3. **去重拒绝**：写入与尾部 10 条/摘要段 ratio > 0.85 的条目 → 拒绝，返回
   最相似条目原文与改写建议。
4. **去重放行**：ratio ≤ 0.85 或比对范围为空 → 正常追加，带持久 ID。
5. **软上限**：压缩窗口内第 6 条写入 → 照常落盘，返回值带
   `hot_entries` 计数与压缩 hint。
6. **压缩优先级**：含 superseded 条目的任务压缩 → 退役条目先进 archive。
7. **分级信号**：30/35/40 条三档任务的 `get_task_context` 返回
   yellow/orange/red；`compaction_due` 与 red 等值。
8. **存量兼容**：无 ID 存量条目注入时带惰性序号；不 supersede 时文件逐字节
   不变。
9. **蒸馏提示**：prepare 响应含修订建议提示句。

## 五、与既有决策的一致性核对

- ADR-0001（Markdown 存储）：不动格式，所有改动是 markdown 内联约定。✓
- ADR-0002（直写无闸门）：写入检查是确定性质量门不是确认闸门，超限放行。✓
- ADR-0007（不做自动冲突发现）：supersede 是显式声明，工程侧只做标记与过滤。✓
- ADR-0008（原料标记去重）：写入检查与原料标记互补——标记防双通道双写，
  检查防同通道重复。✓
- 2026-09-17 mem0 决策：无闸门自动 UPDATE/DELETE 不借鉴；supersede 走显式
  声明 + 降状态保留原文。✓
- tri-state 纪律：写入检查直接 enforce（确定性规则无副作用，与 hit/adopted
  遥测同权）；分级信号是 observe（只报不改）。✓
- Doctrine「不静默失败」：坏 ref 显式报错（先验证后落盘，不留孤儿条目）。✓
- Doctrine「fail-open」：去重拒绝是唯一例外（拒绝即目的，非故障降级）。✓

## 六、明确不做

- mem0 式无闸门自动 UPDATE/DELETE（2026-09-17 决策笔记）
- 半衰期衰减 / TTL（HL-Mem C11 排除，破坏确定性可解释排序）
- 自动冲突发现（ADR-0007，无 slot 底座 + 弱冲突误报前科）
- 蒸馏事件流 + 整数 ID 映射（本期砍掉，与 consolidate 收益重叠）
- 向量检索（多次调研一致排除）
- 跨用户 supersede（注入侧按用户过滤，不可实现）
