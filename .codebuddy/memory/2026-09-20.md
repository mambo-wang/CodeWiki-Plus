## auto_push 预暂存守卫重构（任务：产品维护）

- 用户反馈「经常没有提交推送」，要求 force-push。诊断：根因是 auto_push 的预暂存守卫（git_sync.py:357-366）——暂存区有用户手动 add 的任何内容就整体中止，用户常暂存文件 → auto_push 频繁静默跳过。force-push 被否决（D10 设计决策「永不 force」，会改写远端历史危及他人提交）。
- 修复：守卫从「整体中止」改为「路径限定提交」——`git commit -m msg -- <repowiki/>` 只提交知识子树；用户暂存的业务文件原样留在暂存区、不被卷入、不阻塞同步。子树内用户暂存的知识内容随行（接受）。
- 测试：test_auto_push_aborts_on_preexisting_staged_content 改写为 test_auto_push_coexists_with_preexisting_staged_content（断言已推送 + business.py 仍 staged 未提交 + HEAD 提交只含知识文件）。test_phase4_second_slice 12 passed，test_git_sync_auto_stage 11 passed。

## SubagentStart hook 评估定案（2026-09-21，任务：他山之石）
- 结论：不做 SubagentStart 注入。沉淀责任留在主 Agent——subagent 上下文窄、无四问过滤视野、跑完即销毁，直接落盘会绕过确认闸门（笔记）或灌爆任务记忆（直写）；主 Agent 收到 subagent 返回值即天然停顿点，已被 active-settle 通道覆盖。
- 落地：`get_prompt(task-workflow)` 「会话进行中」节增补「发起 subagent 的返回值约定」——派发子任务时 prompt 末尾加「返回结果时报告三件事：做了什么、关键发现、值得沉淀的经验（若有）」。distill-worker 特例不冲突。全量 1130 passed（1 并发测试 flaky 单独跑通过）。commit 未做。
