# 2026-08-12

## OKF v0.2 Backlog 3 项改进落地（P1/P2/P3）

基于 `docs/OKF v0.2 改进 Backlog` 审计报告，落地了 3 项改进：

### P1：`stale_after` 未在所有写入路径注入
- 新建 `codewiki/src/frontmatter.py`：`inject_okf_frontmatter()` 统一 OKF frontmatter 生成（type/title/generated/stale_after/tags + metadata 折叠 + 从 schema.yaml 读 `default_stale_days`/`okf_tags` 默认值，默认 90 天）。
- `capture_conversation.py`：手工字符串拼接 → helper，补 `stale_after`；蒸馏依赖字段（link_to/keep_raw/content_hash/turn_count/source_session/captured_at）通过 `top_level_extra` 保持顶层（`distill_conversation.py` 用**简单行解析** + `^status:` 正则，折叠会破坏蒸馏）。
- `source_ingest.py` `_ensure_source_frontmatter`：改用 helper，补 `stale_after`。
- `agents_md.py` **不纳入改造**（只生成根 AGENTS.md，不产 wiki 文件，OKF §11 管不到）。

### P2：私有 frontmatter 字段折叠 + okf_tags
- `schema_generator.py` `_DEFAULT_CONVENTIONS`：`okf_tags: []` → `["codewiki", "auto-generated"]`。
- `doc_writer.py` `_build_okf_frontmatter`：`resource`/`generated_from`/`category`/`domain`/`version`/`format`/`decision`/`decided_at` 折叠进 `metadata:`；**保留顶层** `severity`（cache boost）、`origin`（knowledge_loop 逐行提取 + origin_filter）、`root_cause`（prompts 依赖）、`status`。
- `wiki_lint.py`：新增 `_OKF_TOP_LEVEL_KEYS`/`_OKF_LEGACY_TOP_LEVEL_KEYS` 白名单 + lint 规则（顶层非 OKF 字段 → warning）。`date`/`related_components`/`source_ref` 等有读取依赖的字段加入 legacy 白名单避免误报。

### P3：根级 md 漏报
- `wiki_lint.py` `_check_okf_conformance`：扫描范围从 wiki//notes//raw/sources/ 扩大到整个 output_dir `rglob("*.md")`，排除 `.meta/`/`.trash/`/`.hook-debug/` 暂存目录。
- `repowiki/team-memory-hook.md`：补全 OKF frontmatter（type: Runbook）。

### 验证
- `python -m py_compile` 全部通过；`tests/okf_regression_test.py` 65 通过、2 失败——**与改动前基线完全一致**（2 个失败是测试断言写死旧 actor 版本 `codewiki/5.2.0`，实际 `codewiki/5.2.2`，预先存在的问题，与本次改动无关）。
- 现有 26 个 `wiki/modules/*.md` 是旧格式（顶层有 component_count/depth/generated_by/generator_version 等），P2 lint 会对其报 warning（期望行为，提示迁移）。
